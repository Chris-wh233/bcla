# 缺失资源处理

触发条件：已识别的必需非镜像产物尚未验证并可用，包括项目自身二进制、发行包、库、工具及生成文件；在选择源码构建之前触发，不必先构建失败。

目的：优先复用现有资源，避免不必要的源码构建和辅助生成链移植。

功能：按指定顺序检索 LoongArch 来源，上游 Release 最后；验证真实消费者兼容性；必要时从源码构建。若架构无关产物更适合在 x86 生成，则直接记录等待并暂停，不要求先解决其原生生成器依赖。支持用户提供产物恢复，以及 manual/auto 两种 CI 行为。

详细规则见 [SKILL.md](SKILL.md)，来源见 [sources.md](references/sources.md)。

记录产物的实际来源：下载、系统包安装、Dockerfile 阶段内构建、任务期间单独构建或用户外部生成。现成产物可替换原阶段的编译行为，但保留阶段和后续消费路径。gen-maker 据此决定在线下载或本地 COPY，不能因产物已缓存到工作区就改变来源判断。

记录实际查询来源、结果、候选验证或拒绝原因及最终获取路线。已验证资源可直接复用，不必查完低优先级来源；进入源码兜底前则需交代适用来源和 CI。只有文件名含 loong64 不能证明兼容 Alpine，需要检查实际 ABI 和消费结果。

搜索和验证结果记录在资源清单中，并注明产物的消费者。新增依赖时检查该组件的来源和 CI，再评估当前路线；获得产物后回到消费者验证。

Java 发行包、JAR、WAR 使用前需[扫描本地库](references/java-native.md)，包括嵌套 JAR。必需本地库不兼容时，优先寻找同版本 Maven 替代，再评估兼容版本或返回既有兜底路线；替换后验证实际功能。任务和经验记录替换过程，扁平项目只携带已验证的替换后产物。
