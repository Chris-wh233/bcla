# gen-maker：生成扁平构建项目

触发条件：用户要求将已成功完成的 BCLA 任务导出为独立的 Dockerfile/Makefile 项目。不会自动生成知识库经验、恢复原任务或发布镜像。

```text
@BCLA $bcla:gen-maker 为任务 bcla-... 生成扁平构建项目
```

未指定任务时，选择当前会话最近创建的任务，并验证其为 `SUCCEEDED` 且成功证据一致。无法确认会话归属时要求提供任务 ID，不会选全局最新任务或自动换成更早的成功任务。

默认输出到 `<BCLA_HOME>/exports/<任务ID>/`，可显式指定其它目录。保留已有目录中的用户修改，冲突时使用新目录。原任务、工作区、验收文件和知识库保持只读。

## Dockerfile 与产物来源

对比准确的上游或用户模板、实际验收的终版及导出版本，尽量保留阶段结构、顺序、变量、注释、缩进和换行。允许在原编译阶段中下载已验证的现成产物，并保留后续阶段需要的路径。已确认必要的大调整应有任务证据；不为统一排版重新设计成功方案。无参考模板时跳过风格对比。

| 实际来源 | 导出方式 |
| --- | --- |
| 从明确上游或 fix-pkg-miss 来源下载的产物 | 在 Dockerfile 对应阶段按原确切来源在线下载，不携带缓存副本 |
| 已验证的兼容系统包 | 保留包管理器安装方式与必要配置 |
| 任务期间单独构建的产物，包括本地 CI 和用户在 x86 生成的前端资源 | 携带实际验收的产物并本地 COPY，不因为后来发现 Release 就改成下载 |
| 保留的 Dockerfile 阶段内部生成的产物 | 保留阶段内构建及阶段间复制 |
| 实际使用的本地脚本、配置及适配文件 | 仅携带必需输入；需补丁的小文件保留被准备步骤使用的原版和补丁 |

来源以真实执行记录为准，不能按文件扩展名、大小或缓存位置判断。远程来源不可重现时报告具体缺口，不伪造 URL，不把下载产物冒充成本地构建产物。

## 最小扁平项目

根目录仅放 Makefile、Dockerfile、实际消费的脚本/配置/补丁/本地产物，以及必须保留的许可证。追踪脚本、软链接、配置、准备规则等间接依赖，避免遗漏，也不整份复制工作区。

默认不生成 README、报告、来源清单、校验文件、备用 Dockerfile 或未使用脚本。原版和补丁若已用于生成适配文件，不再额外打包重复的生成结果；make 会在构建前生成它。

不为本地 COPY 产物生成 SHA-256 验证命令、ARG、旁路文件或专用验证阶段。内部仍可核对已记录摘要来识别验收内容；远程下载已有的校验与实际功能验证继续保留。

多个最终镜像分别用 `Dockerfile.<目标>`，由同一 Makefile 构建和显式推送。只有上游明确作为独立镜像依赖、且本次任务实际构建的中间镜像才建立扁平子项目；外层 Makefile 不递归构建或推送。构建顺序放在必要的 Makefile 注释和交付回复中。

## 验证与交付

保留真实成功命令的平台、目标阶段、构建参数和基础镜像覆盖。检查每个文件是否为直接/间接构建输入或必要许可证，检查缺失输入、补丁输出、标签映射和相对上游的必要差异。使用 `make -n` 检查构建和推送命令；必要的补丁准备可以本地验证，交付前移除仅为验证生成的输出。

文件整理、证据读取和静态检查可在宿主机执行。实际编译和镜像构建测试需另有用户要求，并继续使用辅助容器。生成项目不隐含授权构建或推送；静态检查通过不代表转换后的 Dockerfile 已实际构建通过。

交付回复说明任务 ID、证据版本、输出目录、用法、前置要求、镜像标签、产物来源和实际验证程度。捆绑产物保证的是镜像组装输入，不代表能从源码重建全部依赖。

完整规则见 [SKILL.md](SKILL.md)、[Dockerfile 共同规则](../../docs/dockerfile-guidelines.md) 和 [Makefile 示例](references/makefile-patterns.md)。
