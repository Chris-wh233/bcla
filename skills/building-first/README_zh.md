# 最小必要适配

触发条件：失败定位到项目自身源码或构建文件，或已有经过验证的镜像/依赖映射需要写入项目文件。

目的：以最小有效修改获得真实可用的目标产物。

功能：定位根因、验证单项修改、记录保留的补丁；与缺包和镜像技能协作；在重复失败或适配范围持续扩大时重新评估并暂停。保留用户要求的版本、功能和产物，禁止凭空编写替代官方 Dockerfile。

详细规则见 [SKILL.md](SKILL.md)。

本技能负责“怎么适配”，不负责决定“是否自行编译”。将二进制下载改成源码构建、引入新原生库构建前，先按 fix-pkg-miss 得到有证据的获取结论；已有结论的正常项目修复不必重复搜索。

Dockerfile 尽量保持准确上游模板的阶段结构与排版。找到并验证现成产物时，可在原编译阶段改为下载，保留后续消费路径，移除不再使用的编译输入。必要的大调整记录原因，最终整理必须在实际构建验收之前完成。共同规则见 [Dockerfile 指导](../../docs/dockerfile-guidelines.md)。

修改假设和验证结果保存在检查点及决策中，并注明对应产物。临时修改若参与成功产物生成，还原前保存精确补丁和执行证据。
