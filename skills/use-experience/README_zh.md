# 复用构建经验

触发条件：已确定仓库、版本和目标，尚未全面分析项目构建逻辑。

目的：使用实际验证过的同项目经验减少重复分析。

功能：同步只读使用的知识库缓存，匹配仓库与版本，检查目标和环境兼容性；尝试最佳适用经验，局部变化交给相应技能修复。知识库不可用或经验根本失效时回到正常分析，不阻断任务。

详细规则见 [SKILL.md](SKILL.md)。

历史源码配方不是“当前没有现成资源”的证明。执行编译步骤前，对尚无有效获取结论的产物交给 fix-pkg-miss；若可复用现成包，只替换产物生成步骤，保留适用的打包和测试流程。知识库未命中也不直接跳到源码编译。

选中经验的来源和适用性记录在决策中。历史成功不能直接计为当前任务事实；新增缺失输入仍由对应技能处理。

新经验按“项目／版本／最终运行基础镜像家族”检索，先过滤目标和用户明确的运行环境约束，再比较版本。要求 Alpine 时不能因 Debian 版本更近就选择 Debian；指定 Debian 辅助容器不代表最终镜像必须是 Debian。无明确家族时参考官方目标变体与实际环境兼容性，同等候选按相对路径稳定排序。

索引过期时扫描同项目的 `<版本>/<家族>/experience.json`，不把依赖经验列为镜像候选。多家族任务可为各自目标选择一份经验；某份经验核心失效后，该家族回到正常分析，不反复尝试旧版或不兼容家族。记录完整经验路径、家族和适用目标；已有 schema 2 经验可读取，但不猜测缺失的家族，不自动迁移。共同约定见 [知识库结构](../../docs/knowledge-layout.md)。
