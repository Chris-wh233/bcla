# BCLA Remote 验证范围

入口为源码根目录的 `make -C remote check`。连接层使用共享核心，不再校验或维护 vendor 快照。

自动检查覆盖：

- Bash/POSIX sh 语法及 Python 源码语法。
- 根构建上下文、Dockerfile 位置及核心版本/revision 构建参数。
- 客户端直接复制当前核心，包含最新知识库与导出规则，排除远端部署和生成目录。
- 客户端再次通过本机安装器打包后保留连接配置、转发脚本及远端规则。
- SSH 参数转义、不分配 TTY、非法连接参数与源码输出目录拒绝。
- Docker 架构检查、同路径绑定、服务复用、配置冲突和非托管容器保护。
- 共享 MCP 初始化、任务创建及跨独立连接读取持久化状态。
- 按会话的一次性工具调用、JSON 参数/错误输出、真实会话过滤，以及调用退出后 worker 继续执行与 request_key 去重。
- 核心任务记录、worker、知识库 schema 3 与索引测试。

模拟部署不证明镜像已构建或远端可用。远端联调时依次检查：

1. deploy.sh build 的完整日志，服务镜像版本/revision 标签及 Linux/LoongArch64 架构。
2. up/status、Docker socket 与同路径 BCLA_HOME 挂载，以及健康检查。
3. 按会话 SSH 工具调用（或可选固定客户端 MCP 连接）、测试任务路径归属、远端任务库持久化。
4. 已准备辅助容器内的短命令及日志/退出码。
5. 断开再连接后的执行恢复，确认没有重复提交。
6. 远端知识库同步、变体经验读取，以及显式 gen-experience/gen-maker 操作的路径归属。

真实联调应使用明确的测试任务与数据目录，不覆盖现有任务。修改核心后重建服务镜像；使用可选固定客户端时再同步重新生成客户端。
